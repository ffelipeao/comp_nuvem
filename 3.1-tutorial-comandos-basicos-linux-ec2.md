# Tutorial — Comandos básicos de Linux em uma instância EC2

Computação em Nuvem · Prof. Felipe

## Objetivo

Aprender a usar o terminal de uma instância EC2 Linux recém-criada: identificar o sistema, navegar entre pastas, manipular arquivos, buscar informações e consultar os recursos do servidor.

**Duração sugerida:** 60 a 90 minutos. **Pré-requisito:** instância em execução e acesso ao terminal funcionando. Para criar e conectar a instância, consulte [Servidor Linux no Amazon EC2](3-tutorial-servidor-linux-ec2.md).

Os comandos de prática funcionam em Ubuntu e Amazon Linux 2023. A instalação de programas tem instruções específicas para cada distribuição.

> Execute os comandos na ordem, um bloco por vez. Tudo a partir da seção 2 deve ser executado **dentro do terminal da EC2**, não no terminal local do seu computador. Não digite os símbolos `$` ou `#` do prompt.

## 1. Entrar no terminal da EC2

Se já está conectado, avance para a seção 2.

Para conectar por SSH, use o comando fornecido na aba **Conectar (Connect)** da sua instância. No terminal local de Linux ou macOS, um exemplo para Ubuntu é:

```bash
chmod 400 ~/Downloads/chave-aula.pem
ssh -i ~/Downloads/chave-aula.pem ubuntu@IP_PUBLICO
```

Substitua o caminho pelo arquivo da sua chave e `IP_PUBLICO` pelo endereço da instância. Em Amazon Linux, use `ec2-user` no lugar de `ubuntu`. Esses usuários dependem da AMI escolhida. [Referência da AWS](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/connection-prereqs-general.html).

No Windows, use o comando SSH da aba **Conectar**, com o caminho local da chave. O comando `chmod` acima é para Linux/macOS.

Para SSH direto pela internet, a instância precisa de conectividade pública e o grupo de segurança deve permitir a porta 22 a partir do seu IP. Também é possível usar **Conectar → EC2 Instance Connect**, quando a instância e a rede atendem aos requisitos dessa opção. [Conexão por SSH](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/connect-linux-inst-ssh.html).

Após conectar, o prompt será parecido com:

```text
ubuntu@ip-172-31-20-15:~$
```

Ele mostra o usuário (`ubuntu`), a máquina (`ip-172-31-20-15`) e a pasta atual (`~`, a pasta pessoal). O `$` costuma indicar um usuário comum; `#` costuma indicar o administrador `root`.

## 2. Entender como um comando funciona

A estrutura mais comum é:

```text
comando opções argumentos
```

Por exemplo, em `ls -lh /etc`, `ls` lista arquivos, `-l` pede detalhes, `-h` facilita a leitura dos tamanhos e `/etc` é a pasta consultada.

- Pressione **Enter** para executar.
- Use **Tab** para completar nomes de arquivos e comandos.
- Use **↑ / ↓** para recuperar comandos anteriores.
- Use **Ctrl+C** para interromper um comando em execução.
- Use **Ctrl+L** ou `clear` para limpar a tela; isso não apaga arquivos.
- Linux diferencia maiúsculas e minúsculas: `Notas.txt` e `notas.txt` são nomes diferentes.
- Nos exemplos, linhas iniciadas por `#` são comentários explicativos.

## 3. Identificar o usuário e o servidor

Execute:

```bash
whoami
hostname
pwd
cat /etc/os-release
uname -r
date
uptime
```

| Comando | O que observar |
| --- | --- |
| `whoami` | Nome do usuário da sessão |
| `hostname` | Nome do servidor |
| `pwd` | Caminho completo da pasta atual |
| `cat /etc/os-release` | Nome e versão da distribuição; observe `NAME` e `VERSION_ID` |
| `uname -r` | Versão do kernel, o núcleo do Linux |
| `date` | Data, hora e fuso configurados no servidor; podem diferir do seu computador |
| `uptime` | Tempo ligado, número de sessões e carga média do sistema |

**Confira:** você está em Ubuntu ou Amazon Linux? Qual é a sua pasta pessoal?

## 4. Navegar pelas pastas

```bash
ls
ls -lh
ls -la
cd /etc
pwd
cd ..
pwd
cd ~
pwd
```

`ls` lista o conteúdo da pasta atual. `-l` mostra detalhes; `-h` mostra tamanhos como KiB e MiB; `-a` inclui arquivos ocultos, cujos nomes começam com ponto.

`cd /etc` usa um **caminho absoluto**, começando na raiz `/`. `cd ..` sobe um nível. `cd ~` volta à pasta pessoal; `cd` sem argumento faz o mesmo. `cd -` volta para a pasta anterior.

| Caminho | Significado |
| --- | --- |
| `/` | Raiz do sistema de arquivos |
| `~` | Pasta pessoal do usuário atual |
| `.` | Pasta atual |
| `..` | Pasta acima da atual |
| `/etc` | Configurações do sistema e dos serviços |
| `/var/log` | Arquivos de registros, chamados logs |
| `/tmp` | Arquivos temporários; não use para guardar trabalhos permanentemente |
| `/home` | Local habitual das pastas pessoais de usuários comuns |

**Prática:** entre em `/var/log`, confira o caminho com `pwd`, liste os arquivos e volte para sua pasta pessoal.

## 5. Criar a pasta de trabalho

Use esta pasta para todos os arquivos da prática. Se já existir uma pasta com esse nome de uma aula anterior, escolha outro nome e adapte os próximos comandos.

```bash
cd ~
mkdir aula-linux
cd aula-linux
mkdir documentos backup
pwd
ls
```

`mkdir` cria diretórios. Aqui, criamos duas subpastas em um único comando. O resultado de `pwd` deve terminar em `/aula-linux`, e `ls` deve mostrar `backup` e `documentos`.

Para criar vários níveis de uma vez:

```bash
mkdir -p projetos/site
```

A opção `-p` cria também as pastas intermediárias necessárias.

## 6. Criar e ler arquivos

```bash
touch documentos/notas.txt
printf 'Minha primeira aula de Linux na EC2\n' > documentos/notas.txt
printf 'Estou aprendendo comandos no terminal.\n' >> documentos/notas.txt
cat documentos/notas.txt
```

`touch` cria um arquivo vazio quando ele não existe; se existir, atualiza suas datas de acesso e modificação. `printf` escreve texto e `\n` representa uma quebra de linha. `cat` mostra o conteúdo.

**Atenção aos redirecionamentos:** `>` cria ou **substitui** o conteúdo do arquivo. `>>` cria ou **acrescenta** ao final. Confira o caminho antes de usar `>`.

Experimente outras formas de leitura:

```bash
head -n 1 documentos/notas.txt
tail -n 1 documentos/notas.txt
wc -l documentos/notas.txt
```

`head` mostra o início; `tail` mostra o fim; `wc -l` conta quebras de linha. Neste exemplo, o arquivo tem duas linhas terminadas por quebra de linha.

Para ler um arquivo longo, se `less` estiver instalado:

```bash
less /etc/services
```

Use as setas para navegar, `/ssh` e Enter para pesquisar e **q** para sair. Se aparecer `command not found`, veja a seção 11.

## 7. Copiar, mover e remover

Ainda dentro de `~/aula-linux`, execute:

```bash
cp documentos/notas.txt backup/notas-copia.txt
ls backup
mv backup/notas-copia.txt backup/notas-antigas.txt
ls backup
cp documentos/notas.txt documentos/rascunho.txt
mv documentos/rascunho.txt backup/
ls backup
```

`cp` copia. `mv` renomeia ou move: o efeito depende do destino. Os arquivos originais continuam em `documentos` após uma cópia. Se o destino já contiver um arquivo com o mesmo nome, `cp` e `mv` podem substituí-lo; use `-i` para pedir confirmação antes de sobrescrever.

Agora remova somente o rascunho criado nesta prática:

```bash
rm -i backup/rascunho.txt
```

`rm` remove arquivos sem enviá-los para uma lixeira. `-i` pede confirmação: responda `y` para confirmar ou `n` para cancelar.

Para remover uma pasta vazia:

```bash
mkdir pasta-vazia
rmdir pasta-vazia
```

`rmdir` recusa pastas com conteúdo. A opção `rm -r` remove uma pasta e seu conteúdo; ela não é necessária nesta atividade.

## 8. Buscar arquivos e filtrar texto

```bash
grep -n 'Linux' documentos/notas.txt
grep -ni 'linux' documentos/notas.txt
find . -type f -name '*.txt'
ls -la /etc | head -n 10
```

| Comando ou opção | Explicação |
| --- | --- |
| `grep` | Exibe as linhas que contêm o texto buscado |
| `-n` no `grep` | Inclui o número da linha |
| `-i` no `grep` | Ignora diferenças entre maiúsculas e minúsculas |
| `find .` | Pesquisa a partir da pasta atual |
| `-type f` | Seleciona apenas arquivos comuns |
| `-name '*.txt'` | Busca nomes terminados em `.txt`; as aspas fazem o padrão chegar ao `find` |
| `\|` (pipe) | Envia a saída de um comando para a entrada do próximo |

No último exemplo, `head` recebe a listagem produzida por `ls` e mostra apenas as dez primeiras linhas. Se `grep` não encontrar o texto, pode terminar sem exibir nada.

## 9. Entender permissões e o comando sudo

```bash
ls -l documentos/notas.txt
chmod 600 documentos/notas.txt
ls -l documentos/notas.txt
```

O resultado deve começar com `-rw-------`: é um arquivo comum; o dono pode ler e escrever; grupo e demais usuários não recebem permissões sobre ele.

As letras significam `r` (leitura), `w` (escrita) e `x` (execução). Em diretórios, `x` permite atravessar/acessar a pasta. No modo numérico, leitura vale 4, escrita vale 2 e execução vale 1. Assim, `600` dá `4 + 2` ao dono e zero aos outros dois grupos.

`sudo` executa um comando com privilégios administrativos, normalmente como `root`. Exemplo de consulta:

```bash
sudo ls /root
```

Não é necessário usar `sudo` para trabalhar nos arquivos da sua própria pasta. Em AMIs oficiais usuais de Ubuntu e Amazon Linux, o usuário inicial geralmente já pode usar `sudo` sem senha; outras imagens podem ter regras diferentes. [Usuários em instâncias EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/managing-users.html).

## 10. Consultar disco, memória, processos e rede

```bash
df -h
du -sh ~/aula-linux
free -h
nproc
ps aux | head -n 10
top
```

**Pressione q para sair do `top`** antes de continuar.

| Comando | Para que serve |
| --- | --- |
| `df -h` | Mostra uso e espaço disponível dos sistemas de arquivos; observe `Use%` e a montagem `/` |
| `du -sh` | Resume o espaço ocupado pela pasta indicada |
| `free -h` | Mostra memória e swap; `available` estima a memória disponível para aplicações |
| `nproc` | Mostra quantas unidades de processamento estão disponíveis ao processo |
| `ps aux` | Lista processos, usuários, consumo de recursos e PID (identificador do processo) |
| `top` | Atualiza a visão dos processos e recursos em tempo real |

Para consultar a rede:

```bash
ip -brief address
ip route
ss -tln
```

`ip -brief address` resume as interfaces e seus endereços. `ip route` mostra rotas, incluindo a saída padrão quando configurada. `ss -tln` lista portas TCP em escuta; a porta 22 costuma aparecer por causa do SSH.

Na EC2, o IPv4 público normalmente não aparece na interface Linux: ela mostra o IP privado. Uma porta em escuta também não significa que ela esteja acessível pela internet; isso depende da rede e do grupo de segurança.

## 11. Instalar programas conforme a distribuição

Confira primeiro:

```bash
cat /etc/os-release
```

Execute **somente o bloco correspondente ao seu sistema**. Estes comandos precisam de acesso aos repositórios pela rede e alteram os programas instalados. Leia a confirmação antes de aceitar.

### Ubuntu

```bash
sudo apt update
sudo apt install nano tree less
```

`apt update` atualiza a lista de pacotes disponíveis; não atualiza sozinho os programas já instalados. `apt install` instala os programas pedidos e suas dependências.

### Amazon Linux 2023

```bash
sudo dnf install nano tree less
```

O Amazon Linux 2023 usa **DNF** para gerenciar pacotes. [Documentação da AWS](https://docs.aws.amazon.com/linux/al2023/ug/package-management.html).

### Experimentar os programas

```bash
cd ~/aula-linux
tree .
nano documentos/notas.txt
```

`tree` mostra a organização das pastas. No `nano`, acrescente uma linha com seu nome. Pressione **Ctrl+O**, **Enter** para salvar e **Ctrl+X** para sair. Confira a alteração:

```bash
cat documentos/notas.txt
```

## 12. Consultar serviços e logs

Um serviço é um programa administrado pelo sistema, como o servidor SSH. Em Ubuntu e Amazon Linux 2023, o `systemctl` permite consultar serviços gerenciados pelo systemd:

```bash
systemctl list-units --type=service --state=running --no-pager
```

Para consultar o serviço SSH, escolha o nome usado pela sua distribuição:

```bash
# Ubuntu
systemctl status ssh --no-pager
```

```bash
# Amazon Linux 2023
systemctl status sshd --no-pager
```

Observe se aparece `active (running)`. Consulte os últimos registros do sistema:

```bash
sudo journalctl -n 20 --no-pager
```

`journalctl` lê os logs do systemd; `-n 20` limita a vinte entradas e `--no-pager` exibe tudo diretamente. As mensagens variam conforme o servidor. Não pare o serviço SSH durante a prática, pois ele é usado para o acesso remoto.

## 13. Pedir ajuda ao próprio Linux

```bash
ls --help
man ls
```

`--help` geralmente mostra um resumo de uso e opções. `man` abre o manual, quando disponível; pressione **q** para sair. Imagens mínimas podem não incluir `man` ou todas as páginas de manual: nesse caso, use `--help`.

```bash
history
```

`history` mostra os comandos registrados pela sessão do shell. Evite digitar senhas ou outros segredos como argumentos, pois podem ficar no histórico.

## 14. Exercício final — Criar um relatório do servidor

Crie um relatório dentro da pasta da aula:

```bash
cd ~/aula-linux
mkdir -p relatorios
printf 'RELATORIO DA INSTANCIA EC2\n' > relatorios/servidor.txt
printf '\nUsuario:\n' >> relatorios/servidor.txt
whoami >> relatorios/servidor.txt
printf '\nData:\n' >> relatorios/servidor.txt
date >> relatorios/servidor.txt
printf '\nSistema operacional:\n' >> relatorios/servidor.txt
cat /etc/os-release >> relatorios/servidor.txt
printf '\nDisco:\n' >> relatorios/servidor.txt
df -h >> relatorios/servidor.txt
printf '\nMemoria:\n' >> relatorios/servidor.txt
free -h >> relatorios/servidor.txt
cp relatorios/servidor.txt backup/servidor.txt
chmod 600 relatorios/servidor.txt backup/servidor.txt
cat relatorios/servidor.txt
ls -lh relatorios/servidor.txt backup/servidor.txt
```

**Explique com suas palavras:**

1. Qual é a diferença entre `>` e `>>`?
2. Por que `cd /etc` funciona de qualquer pasta?
3. Qual é a diferença entre `cp` e `mv`?
4. O que significa a permissão `600`?
5. Qual comando mostra o espaço livre em disco? E a memória?
6. Como o pipe conecta `ls` e `head`?

**Entrega sugerida:** relatório `servidor.txt` e respostas às seis perguntas. Confira o conteúdo antes de compartilhá-lo; não inclua chaves privadas ou credenciais.

## 15. Resolver erros comuns

| Mensagem ou situação | O que verificar |
| --- | --- |
| `command not found` | Confira a grafia e se o programa está instalado; use o gerenciador da sua distribuição |
| `No such file or directory` | Use `pwd` e `ls` para conferir caminho e nome; observe maiúsculas e minúsculas |
| `Permission denied` em um arquivo | Confira dono e permissões com `ls -l`; confirme se está trabalhando na sua pasta |
| `Permission denied (publickey)` ao conectar | Confira usuário da AMI, chave e instância selecionada |
| `Connection timed out` ao conectar | Confira estado da instância, endereço, porta 22 para seu IP e conectividade da rede |
| Bloqueio do `apt` por outro processo | Aguarde a atualização automática terminar e tente de novo; não apague arquivos de bloqueio |
| Comando parece travado | Pode estar esperando entrada ou executando uma tarefa longa; use Ctrl+C se quiser interromper |
| Apareceu um prompt `>` após digitar | Pode haver aspas abertas; pressione Ctrl+C e digite novamente o comando completo |

## 16. Encerrar a prática

Saia da sessão:

```bash
exit
```

Você volta ao terminal local ou encerra a conexão no navegador. **`exit` não desliga a instância.**

Se terminou de usar o ambiente da aula, no console EC2 selecione a instância e use **Estado da instância (Instance state) → Parar instância (Stop instance)**. Aguarde o estado **Parada (Stopped)**. Não escolha **Encerrar instância (Terminate instance)** se pretende guardar o ambiente para outra aula. Parar não elimina todos os custos: volumes EBS e outros recursos associados podem continuar sendo cobrados. [Parar e iniciar instâncias](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/Stop_Start.html).
