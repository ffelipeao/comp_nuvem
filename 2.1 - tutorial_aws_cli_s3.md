# Tutorial Básico --- AWS CLI e Amazon S3

## Computação em Nuvem --- Prática com AWS

### Objetivo

Este tutorial apresenta os passos básicos para instalar e configurar a
**AWS CLI (Command Line Interface)** e utilizar comandos para acessar o
**Amazon S3**.

Ao final da prática, o aluno deverá ser capaz de:

-   Instalar e verificar a AWS CLI;
-   Configurar credenciais de acesso à AWS;
-   Listar buckets e arquivos;
-   Criar arquivos para teste;
-   Enviar arquivos para um bucket S3;
-   Baixar arquivos do S3;
-   Copiar e mover arquivos dentro do S3;
-   Trabalhar com pastas/prefixos;
-   Remover arquivos de teste.

> **Atenção:** utilize somente as credenciais, o bucket e os recursos
> fornecidos pelo professor ou criados na sua conta para esta atividade conforme as orientações abaixo. Nunca compartilhe `Access Key`,
> `Secret Access Key` ou outros dados de autenticação.

------------------------------------------------------------------------

## 1. O que é a AWS CLI?

A **AWS CLI** é uma ferramenta que permite administrar recursos da
Amazon Web Services diretamente pelo terminal.

Formato geral dos comandos:

``` bash
aws <serviço> <comando> [opções]
```

Exemplo:

``` bash
aws s3 ls
```

O comando acima solicita à AWS a listagem dos buckets S3 disponíveis
para o usuário configurado.

# 2. Instalação da AWS CLI

## 2.1 Windows

Baixe e instale a versão mais recente da AWS CLI utilizando o instalador
oficial:

https://aws.amazon.com/cli/

Após a instalação, abra o **PowerShell** ou **Prompt de Comando** e
execute:

``` bash
aws --version
```

Exemplo de retorno:

``` text
aws-cli/2.x.x Python/3.x Windows/...
```

------------------------------------------------------------------------

## 2.2 Linux

Em distribuições Linux x86_64:

``` bash
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
```

Instale o `unzip`, caso necessário.

Ubuntu/Debian:

``` bash
sudo apt update
sudo apt install unzip -y
```

Descompacte:

``` bash
unzip awscliv2.zip
```

Execute o instalador:

``` bash
sudo ./aws/install
```

Verifique:

``` bash
aws --version
```

------------------------------------------------------------------------

## 2.3 macOS

Uma opção é utilizar o Homebrew:

``` bash
brew install awscli
```

Depois:

``` bash
aws --version
```

# 3. Configurando o acesso à AWS

## 3.1 De onde vêm as credenciais?

O comando `aws configure` **não cria credenciais na AWS**: ele salva no computador os dados de uma identidade que já tem acesso à conta.

| Campo | O que é e onde obter |
| --- | --- |
| **AWS Access Key ID** | Identificador da chave de acesso, criado no IAM ou fornecido pelo ambiente de laboratório |
| **AWS Secret Access Key** | Chave secreta correspondente; para usuários IAM, é exibida somente na criação da chave |
| **Default region name** | Código da região usada na aula, por exemplo `us-east-1`; não é uma credencial |
| **Default output format** | Formato das respostas, como `json`; não é uma credencial |

A senha de login do console e a chave `.pem` da instância EC2 **não são** as chaves solicitadas pela AWS CLI.

**Se o professor forneceu credenciais**, use esses dados e avance para a seção 3.4. Se o laboratório forneceu também um **Session Token**, siga a seção 3.5. Em uma conta institucional com IAM Identity Center, prefira o acesso temporário configurado com `aws configure sso`, conforme as orientações da instituição; não crie uma chave IAM por conta própria nesse caso. [Métodos de autenticação da AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-authentication.html).

## 3.2 Criar ou localizar um usuário IAM na sua conta

Se estiver usando sua própria conta para esta atividade e precisar de uma chave de acesso, use um **usuário IAM dedicado à aula**. Não crie chaves de acesso do usuário raiz (**root**).

1. Entre no [console AWS](https://console.aws.amazon.com/) com uma identidade que tenha permissão para administrar usuários IAM.
2. Pesquise **IAM** na barra superior e abra o serviço.
3. No menu lateral, escolha **Usuários (Users)**.
4. Se já existe um usuário preparado para a aula, clique no nome dele e avance para a seção 3.3.
5. Caso contrário, clique em **Criar usuário (Create user)** e informe um nome, por exemplo `aluno-cli-seunome`.
6. Para usar apenas a CLI, não é necessário habilitar acesso ao console para esse novo usuário. Avance para a etapa de permissões.
7. Adicione o usuário ao grupo da aula ou associe a política definida pelo professor. Para esta prática, ela deve permitir listar o bucket e ler, enviar e excluir objetos **somente no bucket/prefixo do aluno**. Não é necessário conceder `AdministratorAccess` nem acesso a todos os buckets.
8. Revise e clique em **Criar usuário (Create user)**.

Criar o usuário ou a chave não concede automaticamente acesso ao S3. As permissões precisam estar configuradas. A listagem geral `aws s3 ls` pode continuar bloqueada quando o acesso é limitado ao bucket da aula.

Se sua conta não permitir criar usuários ou chaves, peça ao professor ou administrador que prepare o acesso. [Criação de usuários IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_users_create.html).

## 3.3 Criar a chave de acesso no console IAM

1. Em **IAM → Usuários (Users)**, clique no usuário da aula.
2. Abra a aba **Credenciais de segurança (Security credentials)**.
3. Localize **Chaves de acesso (Access keys)** e clique em **Criar chave de acesso (Create access key)**.
4. Escolha o caso de uso **Interface de linha de comando — CLI (Command Line Interface)**. Leia as alternativas e confirme a opção solicitada pelo assistente para continuar.
5. Se desejar, adicione uma descrição, como `aula-cli-s3`, e clique em **Criar chave de acesso (Create access key)**.
6. Na tela final, copie o **ID da chave de acesso (Access key ID)** e a **Chave de acesso secreta (Secret access key)** para preencher a CLI. Você também pode baixar o arquivo `.csv` e guardá-lo em local privado.
7. Conclua o assistente somente depois de guardar os dados com segurança.

**Se a chave já existe:** nessa mesma seção, é possível consultar seu ID e estado, mas **não recuperar a chave secreta**. Se não a guardou, crie uma nova chave e desative/exclua a antiga depois de verificar que ela não é usada por outra aplicação. Não apague chaves de outros trabalhos.

Não envie capturas dessa tela nem o arquivo `.csv` para grupos ou repositórios. Ao terminar a atividade, se a chave não for mais necessária, volte a essa seção para **desativá-la** e depois **excluí-la**. [Gerenciamento de chaves IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html).

## 3.4 Preencher a configuração da CLI

No terminal em que executará os comandos S3, configure as credenciais obtidas:

``` bash
aws configure
```

A AWS CLI solicitará:

``` text
AWS Access Key ID [None]:
AWS Secret Access Key [None]:
Default region name [None]:
Default output format [None]:
```

Exemplo:

``` text
AWS Access Key ID [None]: SUA_ACCESS_KEY
AWS Secret Access Key [None]: SUA_SECRET_KEY
Default region name [None]: us-east-1
Default output format [None]: json
```

Substitua `SUA_ACCESS_KEY` e `SUA_SECRET_KEY` pelos valores reais; esses textos são apenas exemplos. Utilize os dados fornecidos para a aula ou a chave do usuário IAM dedicado que você acabou de criar.

O `aws configure` salva as credenciais do perfil padrão em `~/.aws/credentials` e as opções em `~/.aws/config` (no Windows, dentro de `%UserProfile%\.aws`). As credenciais são armazenadas em texto simples: não compartilhe esses arquivos nem os inclua na pasta do projeto. [Arquivos de configuração da CLI](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html).

## 3.5 Quando as credenciais são temporárias

Alguns laboratórios fornecem três valores: **Access Key ID**, **Secret Access Key** e **Session Token**. Nesse caso, as duas chaves sozinhas não bastam.

Depois de preencher `aws configure`, configure também o token no mesmo perfil:

``` bash
aws configure set aws_session_token "SEU_SESSION_TOKEN"
```

Substitua o exemplo pelo token fornecido pelo laboratório. Como esse comando contém uma credencial, ele pode ficar no histórico do terminal; não compartilhe o histórico nem capturas do comando.

Essas credenciais expiram. Quando isso acontecer, obtenha um novo conjunto no ambiente do laboratório e atualize **os três valores**, seguindo as instruções do professor. Ao trocar posteriormente para uma chave IAM de longa duração, remova o campo `aws_session_token` antigo da seção correspondente em `~/.aws/credentials`. [Configuração de credenciais temporárias](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html).

**Se estiver executando a CLI em uma EC2 com uma função IAM (IAM role) já associada:** a CLI pode obter credenciais temporárias automaticamente. Nesse caso, não grave chaves pessoais com `aws configure`; confirme a identidade com o comando da seção 4. A função precisa ter as permissões S3 da atividade. [Autenticação da CLI](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-authentication.html).

> Não envie suas credenciais por WhatsApp, e-mail, GitHub ou qualquer
> repositório de código. Não coloque chaves AWS em arquivos que serão
> versionados.

# 4. Verificando a autenticação

Para verificar qual identidade está sendo utilizada:

``` bash
aws sts get-caller-identity
```

Um retorno semelhante a este deverá aparecer:

``` json
{
    "UserId": "...",
    "Account": "...",
    "Arn": "..."
}
```

Isso indica que a AWS CLI conseguiu utilizar as credenciais
configuradas.



``` bash
ls
```


# 12. Copiando um arquivo dentro do S3

Também podemos copiar um objeto de um local do S3 para outro:

``` bash
aws s3 cp \
s3://NOME-DO-BUCKET/alunos/seu-nome/arquivo.txt \
s3://NOME-DO-BUCKET/alunos/seu-nome/copia-arquivo.txt
```

Em PowerShell, você pode executar o comando em uma única linha:

``` powershell
aws s3 cp s3://NOME-DO-BUCKET/alunos/seu-nome/arquivo.txt s3://NOME-DO-BUCKET/alunos/seu-nome/copia-arquivo.txt
```

------------------------------------------------------------------------

# 13. Movendo ou renomeando um arquivo

Use `mv`:

``` bash
aws s3 mv \
s3://NOME-DO-BUCKET/alunos/seu-nome/copia-arquivo.txt \
s3://NOME-DO-BUCKET/alunos/seu-nome/arquivo-movido.txt
```

Em uma única linha:

``` bash
aws s3 mv s3://NOME-DO-BUCKET/alunos/seu-nome/copia-arquivo.txt s3://NOME-DO-BUCKET/alunos/seu-nome/arquivo-movido.txt
```

O comando também pode mover um arquivo entre "pastas":

``` bash
aws s3 mv s3://NOME-DO-BUCKET/alunos/seu-nome/arquivo-movido.txt s3://NOME-DO-BUCKET/alunos/seu-nome/documentos/arquivo-movido.txt
```

# 14. Enviando uma pasta inteira

Suponha que exista uma pasta local:

``` text

├── arquivo1.txt

└── arquivo3.txt
```

Para enviar todo o conteúdo:

``` bash
aws s3 cp atividade/ s3://NOME-DO-BUCKET/alunos/seu-nome/atividade/ --recursive
```

Confira:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/alunos/seu-nome/atividade/ --recursive
```

------------------------------------------------------------------------

# 15. Baixando uma pasta inteira

``` bash
aws s3 cp s3://NOME-DO-BUCKET/alunos/seu-nome/atividade/ atividade-download/ --recursive
```

------------------------------------------------------------------------

# 16. Sincronizando diretórios

A AWS CLI também possui o comando `sync`.

Para sincronizar uma pasta local com o S3:

``` bash
aws s3 sync atividade/ s3://NOME-DO-BUCKET/alunos/seu-nome/atividade/
```

Para sincronizar do S3 para a máquina:

``` bash
aws s3 sync s3://NOME-DO-BUCKET/alunos/seu-nome/atividade/ atividade/
```

> **Cuidado:** `sync` é mais poderoso que um simples `cp`. Evite opções
> como `--delete` durante esta aula, pois elas podem remover objetos.

------------------------------------------------------------------------

# 17. Removendo um arquivo

Para apagar um objeto:

``` bash

```

Confira:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/alunos/seu-nome/
```

> Execute comandos `rm` somente nos seus próprios arquivos de teste e
> quando autorizado pelo professor.

# 18. Resumo dos principais comandos

  Objetivo                 Comando
  ------------------------ ---------------------------------------------------
  Ver versão               `aws --version`
  Configurar credenciais   `aws configure`
  Ver identidade           `aws sts get-caller-identity`
  Listar buckets           `aws s3 ls`
  Listar objetos           `aws s3 ls s3://BUCKET/`
  Listar recursivamente    `aws s3 ls s3://BUCKET/ --recursive`
  Upload                   `aws s3 cp arquivo.txt s3://BUCKET/`
  Download                 `aws s3 cp s3://BUCKET/arquivo.txt ./`
  Copiar no S3             `aws s3 cp s3://BUCKET/a.txt s3://BUCKET/b.txt`
  Mover/renomear           `aws s3 mv s3://BUCKET/a.txt s3://BUCKET/b.txt`
  Enviar pasta             `aws s3 cp pasta/ s3://BUCKET/pasta/ --recursive`
  Sincronizar              `aws s3 sync pasta/ s3://BUCKET/pasta/`
  Remover objeto           `aws s3 rm s3://BUCKET/arquivo.txt`

# 19. Atividade prática sugerida

Cada aluno deverá executar a seguinte sequência:

1.  Verificar a instalação:

``` bash
aws --version
```

2.  Obter as credenciais conforme a seção 3 e configurar a AWS CLI (inclua o Session Token se o laboratório fornecer credenciais temporárias):

``` bash
aws configure
```

3.  Verificar a identidade:

``` bash
aws sts get-caller-identity
```

4.  Listar o bucket da aula:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/
```

5.  Criar um arquivo contendo seu nome e matrícula.

6.  Enviar o arquivo para sua pasta:

``` bash
aws s3 cp atividade.txt s3://NOME-DO-BUCKET/alunos/seu-nome/
```

7.  Confirmar o upload:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/alunos/seu-nome/
```

8.  Copiar o arquivo dentro do S3:

``` bash
aws s3 cp s3://NOME-DO-BUCKET/alunos/seu-nome/atividade.txt s3://NOME-DO-BUCKET/alunos/seu-nome/atividade-copia.txt
```

9.  Mover/renomear a cópia:

``` bash
aws s3 mv s3://NOME-DO-BUCKET/alunos/seu-nome/atividade-copia.txt s3://NOME-DO-BUCKET/alunos/seu-nome/atividade-final.txt
```

10. Baixar o arquivo novamente para a máquina:

``` bash
aws s3 cp s3://NOME-DO-BUCKET/alunos/seu-nome/atividade-final.txt atividade-download.txt
```

11. Listar o conteúdo final:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/alunos/seu-nome/ --recursive
```

# 21. Erros comuns

## `aws: command not found`

A AWS CLI não está instalada ou não foi adicionada ao `PATH`.

Verifique:

``` bash
aws --version
```

## `Unable to locate credentials`

As credenciais ainda não foram configuradas.

Execute:

``` bash
aws configure
```

## `AccessDenied`

Exemplo:

``` text
An error occurred (AccessDenied)...
```

O usuário não possui permissão para executar aquela operação. Em um
laboratório, isso pode ser intencional.

## `NoSuchBucket`

Verifique se o nome do bucket está correto:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/
```

## `NoSuchKey`

O arquivo/objeto informado não existe no caminho especificado. Confira o
conteúdo:

``` bash
aws s3 ls s3://NOME-DO-BUCKET/ --recursive
```

# 22. Segurança

Durante a utilização da AWS CLI:

-   Não compartilhe `Access Key` e `Secret Access Key`;
-   Não coloque credenciais em código-fonte;
-   Não envie credenciais para GitHub ou GitLab;
-   Utilize apenas o bucket e a pasta definidos para a atividade;
-   Não remova arquivos de outros alunos;
-   Leia o comando antes de utilizar `rm`;
-   Não utilize `--delete` sem compreender seu efeito;
-   Ao terminar um laboratório com credenciais temporárias, siga as
    orientações do professor para descarte ou revogação.
